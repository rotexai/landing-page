RotexAI

Connect your coding agent

Build a RotexAI project with your own Claude Code, Codex or claude.ai. Your agent works in the project with your own rights: it signs in as you, sees what you can see, and changes only what you may change.

This is a preview on our staging environment. Sign in with your staging account.

Before you start

  1. Open the project in the portal, then Team → Coding agents.
  2. Copy the project's URL. It looks like https://staging-mcp.rotexai.com/p/<project id>. Add /all at the end for every tool (data, history and release as well as the core build tools).
  3. Agents can only read until an owner or admin turns on Let coding agents make changes there.

Below, replace <URL> with the project's URL and rotexai-shop with any name you like for this connection.

Claude Code

claude mcp add --transport http rotexai-shop <URL> --client-id rotexai-claude-code
claude mcp login rotexai-shop

Or open /mcp in Claude Code and choose Authenticate. Your browser opens the RotexAI sign-in; approve the access and return to Claude Code.

Codex

Add this to ~/.codex/config.toml:

[mcp_servers.rotexai-shop]
url = "<URL>"
scopes = ["openid"]

[mcp_servers.rotexai-shop.oauth]
client_id = "rotexai-codex"

Then sign in:

codex mcp login rotexai-shop

claude.ai

  1. Open Settings → Connectors → Add custom connector.
  2. Paste the project's URL.
  3. Under Use your own OAuth client, set the client ID to rotexai-claude-ai and leave the secret blank.
  4. Connect, sign in to RotexAI and approve the access.

Ending an app's access

Open your RotexAI account, Applications, and remove the app. The others stay signed in. The app's calls stop within five minutes.

What agents can and cannot do

  • Read the project and its objects, check workflow definitions, and, with changes allowed, create objects, edit files in a sandbox workspace, run commands there and commit and push to the object's repository.
  • Never publish, roll back or unpublish anything: you do that in the portal.
  • Sandbox time counts towards the project's plan, as builds do. Over the plan's limit, commands are refused.
